# SPY 下一交易日 VaR 预测

在交易日结束后，用已知信息预测下一交易日对数收益率的 **1%、5%、10% 左尾分位数**。概率预先给定，输出是收益率界限：例如 5% 分位数为 −2%，表示预测次日收益率低于 −2% 的概率为 5%。

研究围绕三个问题：近期经验分布与动态波动模型如何比较；相同信息下非线性是否有帮助；相同多日输入下循环或注意力结构是否带来额外收益。模型分别运行，验证、评估和比较分开进行。

## 模型

| 配置名称 | 方法 | 输入与作用 |
|---|---|---|
| `historical` | 历史模拟 | 最近收益率的经验分位数，基线 |
| `garch` | GARCH(1,1) | 收益率；预测条件波动，再由正态或标准化 t 分布得到分位数 |
| `linear_qr` | 线性分位数回归 | 当日收益、log(RV5)、log(BV)，带 L1 惩罚 |
| `mlp_qr` | 分位数 MLP | 将 L 日三个指标按日期展开，16 个 tanh 隐藏单元 |
| `gru_qr` | 分位数 GRU | 同样的 L 日指标，单层 16 个隐藏单元 |
| `transformer_qr` | 分位数 Transformer | 同样的 L 日指标，8 维、2 头、单层编码器 |

全部已实现。神经网络直接最小化 pinball loss；训练标签是实际次日收益率，不需要“正确的 VaR 标签”。

## 一次只跑一个模型

在仓库根目录执行：

```bash
python run.py
```

唯一选中的模型由 `config/experiment.yaml` 决定，不接受命令行参数、模型列表或 `all`。

```yaml
model: gru_qr
test_size: 1000
alphas: [0.01, 0.05, 0.10]
data: ../../spy_data.csv
output: ../../results
```

`test_size` 表示最后多少个交易日逐日评估，不是一次预测未来 1000 天。模型参数统一在 `config/<模型名>.yaml`，只读取选中的那一份。每次创建独立结果目录，不覆盖之前的训练结果。

## W 和 L：两个不同的长度

- `window`（W）：每次拟合使用多少个已经兑现的训练标签。
- `lookback`（L）：每个神经网络样本包含多少天的特征历史。

例如 W=1000、L=20：1000 个“20 日输入 → 次日收益率”样本。相邻输入重叠，并不是 20,000 个独立交易日。最早的样本额外需要 19 行历史特征。

预测目标日 i 时，训练标签使用 `[i-W, i)`，每个标签的输入严格早于标签日；预测输入截止于 i 的前一交易日。所有特征标准化只使用本次训练窗口。得到预测后再读取目标日实际值进行评分；第二天整体向前滚动一条，重新训练。过去评估日的真实收益在兑现后可以进入之后的训练窗口。

MLP 将标准化后的 `(L,3)` 展开为 `3L` 维输入；GRU 和 Transformer 保留序列形状。三者使用相同的逐指标标准化，重叠日期按出现次数参与计算。目标收益乘 100 训练、预测再除以 100。每次从头初始化，GRU 的样本初始状态为零，不跨样本或预测日保留状态。

## 先验证选择，再评估

先在 `config/experiment.yaml` 选择一个模型，然后运行：

```bash
python validate.py
```

`config/validation.yaml` 定义候选：W 为 500/1000，神经网络 L 为 1/20，GARCH 分布为 normal/t。每次仍只研究一个模型，候选配置逐个运行。验证段是最后 `test_size` 日之前的连续 500 日；所有候选使用同样的目标日期。

选择标准是三个尾概率的平均 pinball loss。输出目录包含：

- `trials.csv`：每个候选的得分和结果目录。
- `selected_model.yaml`：选出的模型配置。
- `selection.json`：选择规则、日期与参数。
- `validation_snapshot.yaml` 与各候选的完整运行记录。

检查后把 `selected_model.yaml` 的内容复制到相应的 `config/<模型名>.yaml`，再运行 `python run.py`。验证不会自动改动模型配置或自动跑最终评估。当前仓库中的模型 YAML 已保存本次研究经验证选出的配置。

手动复制配置不会自动关联验证目录；请同时保留 `selection.json`。普通运行的 manifest 将选择过程标为 `not recorded`，而不会根据参数猜测它是否经过调优。

本次使用 2012-07-12 至 2014-07-09 的 500 个日期选择参数，2014-07-10 至 2018-06-27 的 1000 个日期评估。20 epochs、网络规模、学习率和正则化固定；只搜索声明的小网格，不代表找到了全局最优配置。最后 1000 日已在先前开发中查看过，因此这些结果是**探索性评估**，不能称为未接触的最终测试结果。

## 比较什么才公平

比较各自验证选出的配置，回答的是完整预测方案谁更好。要研究结构，需要另做控制变量的比较：

| 问题 | 对照 |
|---|---|
| 非线性是否有帮助 | 线性 QR 与 MLP，同 W、单日输入、相同日期 |
| 循环/注意力是否有帮助 | MLP、GRU、Transformer，同 W=1000、L=20、20 epochs、seed=42 |
| 结论是否依赖初始化 | 固定上述 W/L/epochs，MLP 与 GRU 分别用 seeds 17、42、73 |

三种网络的训练设置相同，但相同更新次数不保证都收敛，也不意味着计算成本相同。L=20 时 MLP 有 1027 个参数，GRU 有 1059 个；Transformer 使用更小的编码器，具体参数量与耗时一并报告。

## 评价与已保存运行的比较

- **Pinball loss**：主指标，同一尾概率下越低越好；综合得分为三个尾级别的等权平均。
- **突破率**：实际收益低于预测界限的比例，应接近 1%、5%、10%，不是越低越好。
- **检验**：Kupiec 覆盖率、Christoffersen 一阶独立性及条件覆盖；另保存独立假设下的精确二项检验。p 值大不等于模型正确，1% 尾部事件稀少，尤其需要谨慎解读。
- **成对损失区间**：相同日期的损失差，循环区块 bootstrap（默认块长20、2000次）。95%区间未做多重比较校正，是依赖块长设定的探索性证据。

独立输出可能交叉；统一递增排序，原始值仍保留。比较程序先检查目标日期、概率和真实收益完全一致，不会悄悄取日期交集。

把已完成运行的目录填入 `config/comparison.yaml`，执行：

```bash
python compare.py
```

它只读取结果，不训练模型。各组输出 `metrics.csv`、`predictions.csv`、`daily_loss.csv`、`paired_loss_intervals.csv` 和比较图。比较输出路径固定，再次执行会更新该比较目录；原始模型运行目录不受影响。配置内示例路径对应本次本地研究，克隆仓库后需替换为自己的运行路径。

每个训练目录包含逐日预测、训练起止日期、原始分位数、评价表、配置快照、图和 `run_manifest.json`。Manifest 记录运行状态、数据/源码哈希、依赖版本及耗时。失败运行明确标为 `failed`。实际拟合耗时与绘图等总耗时分开记录。
